## 盤點方法

1. **建置與測試**：`dotnet build Cornhsu.Labeling.slnx -c Release`（.NET SDK 10.0.302，0 警告 0 錯誤）；
   `dotnet test Cornhsu.Labeling.slnx -c Release`：72 + 6 = 78 條全綠（盤點當時、`669b20e` 的數字；本分支後續的 commit 又補了測試，
   目前條數以 `CLAUDE.md` 為準）。`ci.yml` 沒有跑 `dotnet format`，本次不列。
2. **反射列表**：拋棄式 console（`System.Reflection.MetadataLoadContext` 9.0.0，只讀 metadata、不執行目標組件）
   對 Release 產出的四顆組件列出所有 public／protected 型別與成員。nullable 由
   `NullableAttribute`／`NullableContextAttribute` 解碼，`init` 由 `IsExternalInit` modreq 判定，
   預設值取 `RawDefaultValue`。第 1、2 節的簽章就是這個工具的輸出（短型別名版），原始輸出收在附錄。
3. **TFM 一致性**：`Cornhsu.Labeling` 的 netstandard2.0 與 net8.0 兩份輸出逐行 diff（排除組件識別與參考組件行），結果完全一致。

   另跑 `git diff v1.1.0..HEAD`。比對完已 `git worktree remove`。
5. **打包**：`dotnet pack --no-build -c Release` 輸出到 repo 外，檢視 nupkg 檔案清單與 nuspec 相依。
6. **實跑探針**（repo 外的拋棄式 console，以 ProjectReference 引用本 repo 的 `src/`，EF Core 8.0.11）：
   - 例外訊息：在 SQLite in-memory 上逐一觸發每個 throw 點，記錄型別、訊息、`ParamName`。
   - schema：`Database.GenerateCreateScript()` 產出 SQLite／SQL Server／PostgreSQL 三份 DDL。
   - log：自訂 `ILoggerProvider` 攔截 DI 路徑與 `LabelStoreFactory` 路徑的 category、level、EventId、訊息。
